# Установка без Python (альтернатива)

Обычный путь ([install.bat](../install.bat) в корне проекта) требует Python
на машине пользователя — native host запускается как `python native_host.py`.
Здесь то же самое, но native host — собранный `.exe`, Python пользователю
не нужен вообще.

## Компромисс, о котором нужно знать заранее

Собранный `native_host.exe` **не подписан сертификатом**. Неподписанные
PyInstaller-сборки иногда ловят ложные срабатывания антивирусов — это
известное свойство таких сборок, а не что-то специфичное для этого проекта.
Мы проверили: сам протокол native messaging (обмен с Chrome по stdin/stdout)
работает корректно и даже быстрее, чем `python native_host.py` (~110мс на
запуск против ~215мс) — технических проблем нет. Риск ровно один: реакция
антивируса на неподписанный exe.

Если после установки Chrome или антивирус блокирует `native_host.exe` —
без раздумий откатывайтесь на обычный вариант:

```bash
..\install.bat
```

Оба варианта используют один и тот же `%LOCALAPPDATA%\VLESSChrome`, один и
тот же Extension ID и одну и ту же запись в реестре — переключение между
ними безопасно в любую сторону, ничего вручную чистить не нужно.

## Для пользователя: два шага

Если `installer\dist\native_host\native_host.exe` уже собран (лежит в
репозитории или пришёл в архиве с релизом) — Python не требуется вообще:

```bash
installer\install.bat
```

Дальше как обычно: `chrome://extensions/` → «Режим разработчика» →
«Загрузить распакованное расширение» → папка `extension`.

## Для разработчика: как собрать exe

Сборка — единственный шаг, где Python всё-таки нужен (только у вас,
не у пользователей):

```bash
installer\build.bat
```

Скрипт сам поставит PyInstaller, если его нет, соберёт
`native-host-python\native_host.py` в режиме `--onedir` и **проверит
результат по-настоящему** — не просто «файл появился», а реальный обмен
сообщениями по протоколу native messaging (4 байта длины + JSON), как это
делает сам Chrome.

Результат — `installer\dist\native_host\` (`native_host.exe` + папка
`_internal\` с зависимостями, ~29 МБ суммарно). Эту папку и нужно положить
в архив релиза рядом с `xray.exe`, `geoip.dat`, `geosite.dat`, если
раздаёте `installer\install.bat` пользователям без Python.

### Почему `--onedir`, а не `--onefile`

`--onefile` заворачивает всё в один exe, но распаковывает себя во временную
папку **заново при каждом запуске** — это тяжело, если процесс стартует
часто, как здесь (`ping`/`stop` поднимают новый процесс native host на
каждое действие в popup):

| | холодный старт | обычный запуск |
|---|---|---|
| `--onefile` | ~2000 мс | ~340 мс (распаковка каждый раз) |
| `--onedir` | — | ~110 мс, стабильно |

Разница проверена прогонами на этой машине, не теоретическая.

## Файлы

| Файл | Назначение |
|---|---|
| `build.ps1` / `build.bat` | Сборка `native_host.exe` (нужен Python) |
| `install.ps1` / `install.bat` | Установка из уже собранного `dist\` (Python не нужен) |
| `dist\` | Результат сборки — не хранится в репозитории, собирается локально или приходит в архиве релиза |

Диагностика (`check-installation.bat`) и удаление (`install\uninstall.bat`)
общие с обычной установкой — лежат в корне проекта, отдельных копий здесь
нет.
